# Quickstart

From a clean machine to the agent crew opening its first pull request
against a platform repository, in under thirty minutes. This walkthrough
uses the local k3d evaluation path; for the full reference, see
[local development](/installation/local-dev).

<Callout type="info">
  **Eval scope.** This quickstart spins up the full platform on your
  laptop. Customer production installs are moving to the Cluster
  Operator (post-Beta). For staging or production cluster installs
  today, see [the cluster install guide](/installation/cluster).
</Callout>

## Prerequisites

You need:

- Docker Desktop (running)
- An Anthropic API key from
  [console.anthropic.com](https://console.anthropic.com/settings/keys)
- Access to `github.com/TruStacks/trustacks-mvp` (private during Beta)

Install the CLI tools:

```bash
brew install --cask docker
brew install k3d helm kubectl uv node opa oras
```

Then verify with `make doctor` after cloning the repo (next step).

## The thirty-minute path

### 1. Clone and configure

```bash
git clone https://github.com/TruStacks/trustacks-mvp.git
cd trustacks-mvp
cp .env.example .env
```

Edit `.env` and set `ANTHROPIC_API_KEY=<your-key>`. Without it, the
Runner cannot start.

### 2. Bring up the cluster

```bash
make install   # Python venvs + UI deps; about 1 minute
make up        # k3d + all services; about 5 minutes
make seed      # signed policy bundle + demo repos + ArgoCD; about 2 minutes
```

`make seed` is idempotent and re-runs cleanly. See [the local-dev
guide](/installation/local-dev#bring-up) for the full sequence.

### 3. Confirm everything is reachable

```bash
make urls
```

The output table includes URLs and credentials for the UI, Gitea, and
ArgoCD. The UI lives at `http://ui.localtest.me:8080`.

### 4. Run your first analysis

```bash
cd runner && uv sync
uv run trustacks review sample-app-gitea
```

The Code Reviewer streams events live: `started → cloned → tool_call /
tool_result / finding ×N → done`. Copy the analysis ID from the top of
the output.

### 5. Promote the analysis to a pull request

```bash
uv run trustacks plan <analysis-id>
```

The DevOps Engineer agent reads your analysis and the Environment
Profile, generates a CI workflow + Helm chart + ArgoCD Application,
runs the proposal through the OPA policy gate, and on `allow` opens
the PR on the platform repository.

The Coordinator finishes by printing the PR URL. Open it in your browser.

### 6. Review and merge

The PR body explains:

- **What** the DevOps Engineer proposed (file diff + summary).
- **Why** (which rule from the constitution motivated each artifact).
- **Blast radius** (which Applications and Services are affected).
- **Rollback** (how to revert if the deploy goes sideways).

Review like any other PR. When you merge, ArgoCD picks up the change
and deploys it to your local cluster the way it always has.

## What just happened

In thirty minutes, you brought up a full local TruStacks platform,
ran the Code Reviewer against a sample app, watched the DevOps Engineer
emit policy-checked artifacts, and merged the agent crew's first
proposal. The pattern scales: connect a real repo through the UI's
**+ Connect repo** wizard (see [local-dev](/installation/local-dev#connect-your-own-repo))
and the same loop runs against your code.

The platform now remembers your stack via the Environment Profile.
Future analyses respect what is already declared (your CI platform,
scanner, registry, GitOps controller). No re-explaining every session.
